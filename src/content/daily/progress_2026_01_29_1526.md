# [Progress] ScaleFactor 클램핑 버그 수정

## 📋 완료된 작업

### 1. 문제 발견 및 진단

**증상**: "호그와트 대강당" 모델이 여전히 씬에서 너무 크게 표시됨

**디버깅 과정**:

1. `PreviewCanvas.tsx`에 디버깅 로그 추가 (입력/출력 스케일 값 확인)
2. 콘솔 로그 분석:

   ```
   [AutoScale] 📏 hogwarts_grand_hall.glb
     - Size: 12225.78m → 6.00m (×0.0100)
     - 📐 입력 scale: [1, 1, 1]
     - 📐 최종 scale: [0.010000, 0.010000, 0.010000]
   ```

**원인 도출**:

- 정확한 `scaleFactor` 계산값: `6 / 12225.78 = 0.000491`
- 실제 적용된 값: `0.01` (20배 더 큼!)
- **문제**: `autoScaleAsset.ts`에서 `scaleFactor`를 `Math.max(0.01, ...)` 로 클램핑하고 있었음

**근본 원인**:

```typescript
// 버그 코드
scaleFactor = Math.max(0.01, Math.min(100, scaleFactor));
// → 0.000491이 0.01로 강제 변환됨 → 결과적으로 122m로 렌더링
```

### 2. 해결책 적용

**사용자 피드백**: "알고리즘이 정확히 계산하는데 굳이 상한선/하한선이 필요 없다"

**수정 내용**:

```typescript
// 수정 전
scaleFactor = Math.max(0.01, Math.min(100, scaleFactor));

// 수정 후
// 클램핑 제거: 알고리즘이 계산한 정확한 값 사용
```

**적용 파일**:

- `src/utils/autoScaleAsset.ts` (비동기 + 동기 버전 모두)
