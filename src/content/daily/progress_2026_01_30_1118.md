# [Progress] NSSE 핵심 기능 고도화 완료 및 스케일링 시스템 개선 필요

## 완료된 작업 (Phase A~D)

### ✅ Phase A: NSSE 파이프라인 통합

- `AIPipelineOrchestrator`에 `executeNeuroSymbolic()` 메서드 구현
- 4단계 파이프라인: 통합 씬 생성 → 공간 관계 추론 → 스케일 검증 → 시맨틱 역할 배치

### ✅ Phase B: OBB + SAT 충돌 시스템

- `OBBCollisionSystem.ts` 신규 생성
- 15축 SAT(Separating Axis Theorem) 알고리즘 구현
- MTV(Minimum Translation Vector) 기반 충돌 해결

### ✅ Phase C: NavMesh 배치 시스템

- `NavMeshPlacementSystem.ts` 신규 생성
- 그리드 기반 NavMesh 생성 및 접근성 점수 계산
- 통로 차단 방지 로직

### ✅ Phase D: Raycasting 컨테이너 시스템

- `RaycastingContainerSystem.ts` 신규 생성
- 레이-AABB 교차 검사 (Slabs Method)
- 시맨틱 역할별 Y 좌표 제약 조건 (부유, 천장 부착 등)

## 🚨 발견된 문제: 스케일링 시스템 미연동

### 테스트 케이스

**프롬프트**: "호그와트 대강당, 떠다니는 촛불과 긴 테이블"

### 실제 결과

```
[AutoScale] hogwarts_grand_hall.glb
  - Category: buildings | Axis: X
  - Size: 12225.78m → 6.00m (×0.0005)  ← 하드코딩된 카테고리!
```

### 근본 원인 분석

| 기대 (NSSE 설계) | 현실 (AutoScaler) |
|------------------|-------------------|
| AI가 시맨틱 역할 추론 (`environment_container`) | 카테고리 기반 고정 스케일 (`buildings → 6m`) |
| 컨테이너 기준 상대적 스케일 계산 | 개별 오브젝트 독립적 스케일링 |
| `RelativeScalePolicy` 동적 비율 | 하드코딩된 카테고리 테이블 |

### 핵심 문제점

1. **하드코딩 의존**: AutoScaler가 여전히 `categoryDefaultSizes` 하드코딩 테이블 사용
2. **역할 불인식**: 호그와트 대강당이 `environment_container`(다른 오브젝트를 담는 컨테이너)임을 인식 못함
3. **파이프라인 미연동**: NSSE에서 추론한 시맨틱 역할이 렌더링 시점의 AutoScaler까지 전달 안됨

## 다음 단계: AutoScaler ↔ NSSE 연동

### 필요한 작업

1. **AutoScaler 리팩토링**
   - 하드코딩된 카테고리 테이블 제거
   - 시맨틱 역할(SemanticRole) 기반 스케일 추론으로 전환

2. **컨테이너 인식 로직**
   - `environment_container` 역할의 오브젝트를 기준점으로 설정
   - 내부 오브젝트는 컨테이너 대비 상대적 비율로 스케일

3. **파이프라인 데이터 흐름**

   ```
   UnifiedSceneGeneration → SemanticRole 추론
                         ↓
   RelativeScalePolicy   → 상대적 비율 계산
                         ↓
   AutoScaler (렌더링)   → 실제 스케일 적용 ← 여기가 끊김!
   ```

## 결론

**기하학적 배치 시스템(충돌/네비/컨테이너)**은 완성되었지만, **스케일링 시스템이 NSSE 파이프라인과 연동되지 않아** 실제 씬에서 올바른 스케일이 적용되지 않음.

**우선순위**: AutoScaler를 하드코딩 카테고리 기반에서 **AI 시맨틱 역할 기반**으로 전환해야 함.
