# [R&D] 에셋 URL 404 해결 및 DB 데이터 정합성 확보 (2026-01-23)

## 1. 개요 (Overview)

- **목표**: 클라이언트 에셋 로딩 실패(404) 해결, DB 데이터 정합성 확보
- **진행률**: 에셋 파이프라인 디버깅 및 수정 완료, DB 재시딩 완료 (100%)

## 2. 상세 작업 (Details)

### 작업 1: Asset URL 404 에러 디버깅 및 수정

- **이슈**: 클라이언트에서 특정 에셋(예: `qX3VzA8n5i`) 로딩 시 404 에러 발생. 브라우저 콘솔에 `${POLY_PIZZA_CDN}/qX3VzA8n5i` 형태로 템플릿 변수가 그대로 노출됨.
- **원인 분석**:
  1. `remote_assets.ts`에서 템플릿 리터럴 사용: `` `${POLY_PIZZA_CDN}/7bSuDNx5dqi` ``
  2. `seed_all_assets.js`가 파일을 텍스트로 읽어 파싱하는 과정에서 변수가 평가되지 않고 문자열 `"${POLY_PIZZA_CDN}/..."`로 DB에 저장됨
  3. 클라이언트가 DB에서 받은 URL을 그대로 HTTP 요청하여 404 발생
- **해결 과정**:
  1. **검증 스크립트 작성** (`check_db_urls.js`): DB에서 템플릿 변수가 포함된 레코드 검색
  2. **자동 수정 스크립트 작성** (`fix_remote_assets.js`):
     - Node.js `fs` 모듈 사용 (Powershell 인코딩 문제 회피)
     - 정규식으로 모든 `${POLY_PIZZA_CDN}` → `https://api.poly.pizza/v1/download` 치환
  3. **DB 재시딩 실행**: `seed_all_assets.js` 재실행으로 1,864개 에셋 색인
- **결과**:
  - DB 내 모든 에셋 URL이 유효한 절대 경로로 갱신됨
  - 클라이언트 404 에러 원천 차단
  - Exit code: 0 (성공)

### 작업 2: 월드 생성/입장 플로우 안정화 (전일 누락분)

- **내용**: `ScenarioSelector` → `GameHUD` → `DynamicModel`로 이어지는 데이터 흐름 검증
- **수정**:
  - `ScenePlanner` JSON 스키마를 `ResourceMatcher`와 연동
  - 환경 변수 처리 일관성 확보 (Vercel ↔ Local)
- **검증**: 로컬 환경(8090 포트)에서 시나리오 선택 → 3D 씬 로딩 성공
