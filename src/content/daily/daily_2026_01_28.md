## 3. 상세 작업 (Details)

### 작업 1: Phase 2.5 - Scale Normalization (스케일 정규화)

**문제**: `hogwarts_grand_hall` 등 대형 GLB 에셋(150m+)이 씬을 덮어버리는 문제 발생. 하드코딩된 스케일 값(`DynamicModel.tsx`)이 실제 렌더링 경로(`PreviewCanvas.tsx`)에 적용되지 않음.

**해결**:

1. **GLBModelInner 수정**: `useGLTF` 로드 직후 `THREE.Box3`로 바운딩 박스 측정.
2. **Category-Aware Scaling**:
   - `buildings`: 최대 8m 제한 (씬 뷰포트 맞춤)
   - `characters`: 1.8m
   - `props`: 0.3~0.8m
3. **결과**: 호그와트 대강당이 적절한 크기(8m)로 렌더링되어 테이블/촛불과 조화.

**파일**: `src/components/studio/PreviewCanvas.tsx`

### 작업 2: Phase 2.5 - Hybrid Search & RRF Fusion

**문제**: "긴 테이블" 검색 시 단순 벡터 검색으로는 정확도 부족, 영어 키워드 매칭 실패.

**해결**:

1. **Korean Synonym Dictionary**: 55개 매핑 추가 (긴 테이블 -> long dining table, 촛불 -> floating candle 등).
2. **Reciprocal Rank Fusion (RRF)**: 벡터 검색(Semantic)과 키워드 검색(Lexical) 결과의 순위 합산 알고리즘 도입.
3. **Global Deduplication**: `AssetRetrievalService`에서 URL/Name 기반 중복 제거 필터 `Set` 적용.

**파일**:

- `src/services/VectorSearchService.ts`
- `src/services/ai-pipeline/AssetRetrievalService.ts`

## 4. 트러블슈팅 (Issues)

### 이슈 1: 렌더링 경로 불일치

- **현상**: `DynamicModel.tsx`를 수정해도 뷰포트에서 변화 없음.

## 5. 인사이트 (Insights)

- **Scale Relativity**: 절대 크기보다 **상대적 비율**이 중요함. 8m 건물과 1.8m 캐릭터의 비율이 시각적 현실감을 결정.
- **Search Latency**: RRF와 동의어 처리가 추가되었으나 `Promise.all` 병렬 처리로 응답 속도 유지.
