# 다중 AI 에이전트 기반 스토리버스(Storyverse) 엔진 개발을 위한 심층 기술 조사 및 상세 설계서

## 1. 서론: 생성형 AI 시대의 서사적 패러다임 전환과 스토리버스(Storyverse)

### 1.1 연구 배경: 선형적 텍스트에서 동적 세계로의 진화

인공지능(AI), 특히 대규모 언어 모델(LLM)의 급격한 발전은 디지털 콘텐츠 생성의 근본적인 문법을 재정의하고 있다. 과거의 절차적 콘텐츠 생성(Procedural Content Generation, PCG)이 사전에 정의된 규칙과 난수 발생에 의존하여 제한적인 다양성을 제공했다면, 현재의 생성형 AI는 맥락을 이해하고 창의적인 결과물을 산출하는 능력을 갖추었다. 그러나 단일 LLM에 의존한 콘텐츠 생성은 일관성 유지의 어려움, 환각 현상(Hallucination), 그리고 텍스트와 멀티모달 에셋 간의 괴리라는 한계에 봉착해 있다.

이러한 한계를 극복하고 사용자의 개입에 따라 실시간으로 확장되며 시각화되는 몰입형 서사 공간, 즉 '스토리버스(Storyverse)'를 구축하기 위해서는 단순한 모델 호출을 넘어선 복합적인 아키텍처가 요구된다. 스토리버스는 '스토리(Story)'와 '메타버스(Metaverse)'의 합성어로, 정적인 서사가 아닌 사용자와 AI 에이전트(Agent)의 상호작용을 통해 끊임없이 진화하는 동적 생태계를 의미한다.

본 보고서는 이러한 스토리버스 엔진을 구현하기 위한 핵심 기술 요소인 **다중 에이전트 오케스트레이션(Multi-Agent Orchestration), 지식 그래프(Knowledge Graph) 기반의 일관성 제어, 그리고 생성형 3D/오디오 파이프라인의 자동화**를 심층적으로 분석하고, 이를 통합한 상세 설계안을 제시하는 것을 목적으로 한다.

### 1.2 연구 범위 및 기술적 접근 방법론

본 연구는 상용화 가능한 수준의 엔진 설계를 목표로 하며, 다음과 같은 4가지 핵심 기술 영역에 집중한다.

1. **에이전트 아키텍처의 고도화**: 기존의 선형적 체인(Linear Chain) 구조가 아닌, 순환적(Cyclic) 그래프 기반의 상태 관리와 반성(Reflection) 메커니즘을 지원하는 LangGraph 프레임워크를 분석한다.
2. **서사적 정합성(Consistency) 확보**: 비정형 텍스트 데이터에서 엔티티를 추출하여 구조화하고, Neo4j의 시공간(Spatial-Temporal) 연산 기능을 활용하여 논리적 모순을 실시간으로 탐지하는 알고리즘을 설계한다.
3. **멀티모달 에셋 파이프라인 자동화**: 텍스트 묘사를 3D 모델(Meshy API)과 오디오(Suno API)로 변환하고, 이를 대규모 월드 스트리밍 표준인 3D Tiles(Py3DTiles)로 최적화하는 전 과정을 자동화한다.
4. **시스템 확장성 및 최적화**: 마이크로서비스 아키텍처(MSA)를 기반으로 Python(백엔드/데이터 처리)과 TypeScript(프론트엔드/상태 동기화)의 하이브리드 기술 스택을 제안한다.

## 2. 다중 에이전트 오케스트레이션: LangGraph 기반 순환 아키텍처

단일 AI 모델은 복잡한 장기 기억 유지와 다단계 추론에서 한계를 보인다. 스토리버스 엔진은 각기 다른 역할을 수행하는 전문화된 에이전트들이 협업하는 다중 에이전트 시스템(Multi-Agent System, MAS)을 통해 이를 해결해야 한다. 본 장에서는 LangChain 생태계의 최신 오케스트레이션 프레임워크인 LangGraph를 중심으로 순환적 워크플로우 설계 방안을 논한다.

### 2.1 선형 체인(Chain)에서 순환 그래프(Graph)로의 전환

전통적인 AI 애플리케이션은 입력에서 출력으로 이어지는 방향성 비순환 그래프(DAG) 형태를 띠었다. 그러나 서사 창작과 같은 복잡한 작업은 '작성(Draft) -> 검토(Critique) -> 수정(Refine)'과 같은 반복적인 피드백 루프를 필요로 한다.

#### 2.1.1 LangGraph의 아키텍처 철학

LangGraph는 에이전트 워크플로우를 노드(Node)와 엣지(Edge)로 구성된 그래프로 모델링한다.

- **상태(State) 중심 설계**: 그래프 내의 모든 노드는 공유된 '상태 객체(State Object)'를 읽고 쓸 수 있다. 이는 에이전트 간의 통신 프로토콜 역할을 하며, 각 단계의 실행 결과가 누적되는 메모리 공간이 된다.
- **순환성(Cyclicity)**: LangGraph는 명시적으로 순환(Cycle)을 지원한다. 이는 에이전트가 특정 조건이 만족될 때까지 이전 단계로 되돌아가 작업을 반복 수행할 수 있게 함으로써, 결과물의 품질을 점진적으로 향상시키는 반복적 개선(Iterative Refinement)을 가능하게 한다.

#### 2.1.2 상태 스키마(State Schema)의 엄격한 정의

다중 에이전트 환경에서 가장 치명적인 문제는 데이터 오염과 환각이다. 이를 방지하기 위해 LangGraph는 타입이 지정된 상태 스키마(Typed State Schema)를 강제한다. Python의 TypedDict 또는 Pydantic 모델을 사용하여 상태의 구조를 정의하며, 이는 시스템의 안정성을 보장하는 계약(Contract) 역할을 수행한다.

```python
from typing import TypedDict, Annotated, List, Union
import operator

class AgentState(TypedDict):
    # 메시지 기록: 이전 대화 내역을 보존하며, 덮어쓰기가 아닌 추가(append) 방식으로 관리
    messages: Annotated[List[str], operator.add]
    # 서사 컨텍스트: 현재 씬, 등장인물, 시간적 배경 등의 구조화된 정보
    story_context: dict
    # 생성된 에셋 메타데이터
    generated_assets: List[dict]
    # 비평 및 피드백 데이터
    critique_feedback: str
    # 재시도 횟수 제어 (무한 루프 방지)
    revision_count: int
```

### 2.2 고도화된 에이전트 패턴: Reflexion 및 계층적 구조

#### 2.2.1 Reflexion(반성) 에이전트 패턴

Reflexion은 에이전트가 자신의 행동 결과를 스스로 평가하고 개선하는 패턴이다. 이는 'Generator(생성자)'와 'Reflector(반성자)' 두 가지 역할로 구성된다.

- **Generator Node**: 사용자의 요청에 따라 1차 결과물(초안)을 생성한다.
- **Reflector Node**: 생성된 결과물을 비평가(Critic)의 관점에서 분석한다. 이때 단순히 "나쁘다"는 평가가 아닌, 구체적인 개선점과 논리적 오류를 지적하는 '구두 피드백(Verbal Feedback)'을 생성하여 상태(State)에 추가한다.
- **Conditional Edge**: 평가 결과가 기준치(예: 점수 8점 이상)에 도달하지 못하면, 그래프의 흐름을 다시 Generator로 되돌린다. 이때 Generator는 Reflector가 남긴 피드백을 프롬프트 컨텍스트로 함께 입력받아 이전보다 개선된 결과물을 생성한다.

## 3. 서사적 정합성 제어: 지식 그래프(Knowledge Graph) 시스템

### 3.1 텍스트의 지식 그래프 변환 (Text-to-Graph Pipeline)

LLM이 생성한 유동적인 텍스트에서 확정적인 사실(Fact)을 추출하여 "Ground Truth"를 형성하는 과정이다.

#### 3.1.1 엔티티 추출 및 관계 정의

LLM에게 텍스트를 입력하고, 사전에 정의된 스키마에 따라 노드와 엣지를 추출하도록 한다.

- **Nodes**: Character(인물), Location(장소), Item(사물), Event(사건), Organization(조직).
- **Edges**: (:Character)-->(:Character), (:Character)-->(:Location), (:Event)-->(:Event).

#### 3.1.2 엔티티 명확화(Entity Disambiguation)

가장 중요한 기술적 난제는 중복 노드의 생성 방지다. 텍스트 상의 "해리", "그 소년", "포터"가 모두 동일 인물임을 식별해야 한다.

- **벡터 유사도 기반 병합**: 추출된 엔티티의 이름과 속성을 임베딩하여 기존 그래프의 노드들과 유사도를 계산한다. 유사도가 임계값 이상일 경우, 새로운 노드를 생성하지 않고 기존 노드에 속성을 병합(Merge)하거나 엣지를 연결한다.

### 3.2 시공간(Spatial-Temporal) 추론 및 모순 탐지 알고리즘

#### 3.2.1 공간 데이터 모델링 및 거리 연산

Neo4j의 Spatial 기능을 활용하여 각 장소 노드에 물리적 좌표를 부여한다.

- **CRS (Coordinate Reference Systems)**: `POINT({x: 100, y: 200, z: 10})`와 같이 3차원 좌표로 저장.
- **거리 제약 검증**: `point.distance(A, B)` 함수를 사용하여 이동 가능 여부 검증.

#### 3.2.2 시간 데이터 모델링 및 인과성 검증

시간은 단순한 문자열이 아닌 Date, LocalDateTime, Duration 타입으로 엄격하게 관리된다.

- **이벤트 타임라인**: 모든 사건 노드는 start_time과 end_time 속성을 가지며, 사건 간에는 (:Event)-->(:Event) 관계가 형성되어 시간순 연결 리스트(Linked List) 구조를 이룬다.
- **인과율 및 중복 검증**: 캐릭터는 동일한 시간대에 서로 다른 두 장소에 존재할 수 없다. `E1.end > E2.start` 조건이 탐지되면 "동시간대 중복 등장 오류"를 발생시킨다.

## 4. 멀티모달 에셋 파이프라인 자동화

### 4.1 생성형 3D 에셋 파이프라인: Meshy API 및 최적화

- **Text-to-3D**: Meshy API 활용. Preview(빠른 생성) -> Refine(고품질 변환) 2단계 접근.
- **최적화**: `glTFpack`(메쉬 단순화, KTX2) 및 `Draco`(압축) 적용.

### 4.2 대규모 월드 스트리밍: OGC 3D Tiles 표준 적용

- **3D Tiles 변환**: `py3dtiles` 등 활용하여 GLB를 타일셋(b3dm, json)으로 변환.
- **HLOD**: 카메라 거리에 따라 LOD 자동 교체.

### 4.3 생성형 오디오 시스템: Suno API 통합

- **맥락 기반 BGM**: 에이전트가 분위기에 맞는 프롬프트 생성 -> Suno API 호출.
- **동기화**: 가사 및 비트 타임스탬프 활용.

## 5. 클라이언트 렌더링 (R3F + WebGPU)

- **3D Tiles Renderer**: `3d-tiles-renderer-js`를 R3F 컴포넌트로 래핑하여 사용.
- **WebGPU**: 대규모 인스턴싱 및 컴퓨트 쉐이더 활용.

## 6. 결론

이 설계서는 차세대 콘텐츠 플랫폼 개발을 위한 청사진이며, 기술의 발전 속도에 맞춰 지속적으로 업데이트되어야 할 살아있는 문서이다.
